# Prism v0.2.13

## 内核与 TUN 稳定性

- TUN 关键收发、协议栈任务意外退出或 panic 时记录故障并让内核明确失败退出，避免留下存活但不工作的进程。正常空闲和发送环满不会直接触发重启。
- Windows 接收侧在等待下游队列前释放 Wintun 数据包；补齐不可恢复读写错误处理。
- Windows 增加默认路由和 IP 接口变化通知，并保留轮询兜底；保留快速断开重连的失效标记，修正恢复失败后切回原接口时漏掉重试的问题。
- 排除软修复和冷却自身耗时，避免慢修复反复被误判为休眠唤醒。
- 自动软修复使用最后成功应用的配置，避免读取过期或损坏的磁盘配置；保持运行模式、所选节点、统计及 fake-IP 映射。显式配置重载仍会读取并校验新配置。

## 服务独立恢复

- 开启自动恢复后，新版 TUN 服务可在桌面界面退出时处理 Prism 内核异常退出，包括控制器 API 就绪前的启动失败。
- 服务自动硬重启至少间隔 60 秒，滚动 10 分钟内最多 3 次；GUI 发起的服务硬重启共用这份限额。手动停止或关闭自动恢复会撤销相应恢复意图。
- 自动重启保留最近成功同步的配置、模式和选择组状态，重启前应用选择状态，并在核心替换期间保留断网保护。状态同步失败会暂停独立恢复并报告错误。
- 服务独立恢复目前覆盖进程退出和关键任务故障。存活但不通的端到端探测及分级软修复仍由桌面程序负责，不应退出桌面程序后假定所有网络黑洞都能被识别。

## 诊断与观测

- 设置页显示服务监护状态及恢复次数，新增“导出脱敏诊断”。
- 增加内核运行时间、关键任务、TUN 收发、队列压力及切网修复次数和耗时指标；Windows 另提供内存、句柄和累计 CPU 时间。
- 服务保留最近 5 份脱敏故障快照，不包含订阅、节点凭据、域名、数据包或原始日志，不自动上传。

## 更新步骤

1. 安装更新，完整退出并重新打开 Prism。
2. **使用 TUN 的用户请在设置中“重新安装 / 更新内核”，完成 TUN 服务更新。** 服务保存独立的内核副本，仅更新界面程序不能启用全部改进。按提示批准系统权限请求。
3. 检查自动恢复开关和服务监护状态。发生问题时可导出脱敏诊断，保留触发原因和恢复记录。

Windows 安装包、macOS Intel / Apple Silicon 安装包和现有签名更新通道保持兼容。Windows 路由变化通知和 WFP 断网保护仅适用于 Windows；macOS 包含共用的配置修复、诊断及服务恢复改进。

本次为已验证故障路径的修正及观测完善。历史长时间断网根因尚未完全复现，72 小时 / 7 天真实休眠、切网和持续使用测试尚未完成，不能据此保证所有断网问题已彻底解决。

# Prism 内核与 TUN 稳定性验证

第一阶段关注可定位的故障、受控恢复和可比较的证据。进程存活、连接数量不变、空闲时没有流量，都不能单独证明网络正常或异常。历史上的“进程仍在、重启后恢复”尚不足以确定根因。

## 已实现的观测与恢复

- 受控制器认证保护的 `GET /prism/health` 提供进程运行时间、关键任务状态、TUN 收发计数、队列峰值、最长排队等待和发送环满丢包计数。Windows 还提供工作集、私有内存、句柄数和累计 CPU 时间；其他系统这些资源字段暂为 null。
- 关键收发、协议栈和接入任务意外退出或 panic，会记录固定故障类型并让内核失败退出，避免只留下存活的空壳进程。普通空闲和发送环满不会触发退出。
- Windows 接收侧在等待下游队列前释放 Wintun 数据包，避免把驱动缓冲区占用时间延伸到下游等待期间。不可恢复的读写错误不再被静默忽略。
- 开启自动恢复后，新版服务可在桌面界面不运行时处理 Prism 内核异常退出。自动硬重启统一经过服务限速：间隔至少 60 秒，滚动 10 分钟内最多 3 次。显式停止会撤销恢复意图。
- 服务保留最近成功同步的热重载配置、模式和选择组状态。重启前恢复选择状态，避免先使用默认节点再切回；状态同步失败会禁用独立恢复并返回错误，避免使用过时配置。
- GUI 仍负责端到端联网、DNS 和路由探测及软修复。服务独立恢复目前覆盖进程退出和关键任务故障，尚不独立判断所有“进程存活但网络黑洞”的情况。
- 设置页可导出诊断 JSON。服务保存最近 5 份故障记录；只保存白名单指标、固定故障类型和系统错误码，不包含订阅、节点凭据、域名、数据包或原始日志。

这些机制需要匹配版本的客户端、内核和 TUN 服务。仅替换界面程序无法升级服务独立保存的内核副本。

## 只读长期采样

在测试机使用 Python 3，先从本机控制器配置确认地址及 secret；不要把 secret 发到 issue 或聊天中。以下 PowerShell 命令使用交互输入，避免将密钥写入命令历史：

```powershell
$controllerCredential = Get-Credential -UserName controller -Message '密码栏输入本机控制器 secret'
$env:PRISM_CONTROLLER_SECRET = $controllerCredential.GetNetworkCredential().Password
python -X utf8 scripts/stability_observe.py --controller http://127.0.0.1:9097 --seconds 259200 --interval 5 --output artifacts/stability/prism-72h.jsonl
Remove-Item Env:PRISM_CONTROLLER_SECRET
```

无 secret 的测试控制器可省略前两行。脚本只允许字面量回环 IP，禁止代理及重定向，响应有大小限制，输出文件不能覆盖已有结果。它不会修改路由、重启内核或产生互联网测试流量。控制器不可达会记录错误分类，不保存响应正文。采样有错误时不要仅凭 PID 变化次数计算可用率。

指标是进程生命周期累计值，重启后归零；CPU 时间用相邻采样差值计算，队列峰值与最长等待不能当成实时队列长度。无流量时 RX/TX 不变属于正常现象。

## 评估矩阵与阶段目标

在相同 Windows、节点、网络、规则和 DNS 设置下，对比 Prism / sing-box 的系统代理与 TUN 四种组合。每组分别记录 DNS 正确性、请求成功率、延迟、吞吐、CPU、内存、句柄及恢复时间。仅比较相同业务负载，不能把不同节点质量差异归因于内核。

| 场景 | 验证重点 |
| --- | --- |
| 正常上网、长连接、UDP、突发并发、空闲 | 不误重启；队列压力可观察；资源不持续增长 |
| 休眠唤醒、Wi-Fi 切换、默认路由变化 | 探测能发现失效链路；恢复后 DNS 与实际出口一致 |
| DNS 上游不可达、代理节点不可达 | 能区分解析与出口故障；软修复失败才升级恢复 |
| 收发任务退出、panic、内核进程退出 | 保存脱敏证据；服务有界恢复；配置和选择保持 |
| 手动停止、自动恢复关闭、连续失败 | 不复活；恢复限速生效；保护状态可解释 |
| 断网保护与应用例外、IPv4/IPv6 | 独立验证允许范围与泄露；DIRECT 仍可能经 TUN |

阶段目标建议：先完成隔离故障回归，再在专用测试机连续 72 小时，随后连续 7 天；期间包含休眠、切网、空闲和真实业务。目标为无未恢复黑洞、无空闲误重启、无 DNS 泄露；恢复时间分位数和资源增长趋势需由实测报告给出。上述时长是待执行的门槛，不是已经获得的结果。

后续根据实测证据决定通知策略、传输连接池、队列和协议栈的进一步优化。先保留同环境基线，单独变更一项，避免同时升级多个依赖后无法判断收益和回归来源。

## 第二阶段：切网恢复与当前配置保持

Windows TUN 增加默认路由和 IP 接口变化通知，通知回调只发送信号；实际接口查询和会话修复在异步监控任务中执行。200 毫秒固定合并窗口减少连续事件的重复处理，软修复尝试至少间隔 3 秒；原有 3 秒轮询继续兜底。注册通知失败时退回轮询，不阻止 TUN 启动。

当前出口默认路由或接口被删除时，会保留失效标记，即使快速重连后接口、地址和网关与断开前相同，也会重建 DNS 和代理会话。TUN 自身的接口及非默认路由变化不触发出口失效。通知不是实际连通性的证明，GUI 仍通过联网探测检查存活但不通的情况。

修复失败会保留待重试状态，包括 A → B 失败后再次回到 A 的情况。休眠判断只计算等待网络检查的时间，排除修复及冷却自身耗时，避免慢修复反复被误认为唤醒。

自动会话修复及 provider 内容更新现在从最后成功应用的配置重建；显式配置重载才读取磁盘或新 payload。失败的配置更新不会覆盖这份运行配置。模式、选择组、统计和 fake-IP 映射按既有机制保留。诊断新增 Windows 切网修复成功次数、失败次数和最近一次耗时；这些计数不包括 GUI 发起的所有修复，也不代表互联网可用率。

系统 API 的回调数据不完整，接口完整状态必须另行查询；注销通知在回调外执行，避免死锁。实现依据：[NotifyRouteChange2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-notifyroutechange2)、[NotifyIpInterfaceChange](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-notifyipinterfacechange)、[CancelMibChangeNotify2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-cancelmibchangenotify2)。

隔离回归覆盖快速删除/重建事件、TUN 事件过滤、原生通知注册注销、失败切网后回到原接口，以及磁盘配置过期/损坏时的软修复。真实 Wi-Fi 切换、休眠唤醒和 72 小时 / 7 天持续测试仍须在专用测试机执行。

## 安全测试边界

自动化单元和服务恢复测试使用临时子进程及回环网络，不接管当前主机 TUN。真实网卡、DNS 防护与 WFP 阻断测试仅在隔离 CI 或有本地控制台的专用测试机执行；不要用正在承担远程访问的电脑做故障注入。
